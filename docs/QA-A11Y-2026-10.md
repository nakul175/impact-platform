# Accessibility conformance, bounded subset — October 2026

Branch `qa/2026-10-accessibility`, based on `integration/0.21-0.24` (build 0.24.0, schema 26). Part of v0.26 (VF-UX-001); no build, schema, API or contract version change; no server code changed. Statement for readers outside engineering: `docs/current/ACCESSIBILITY-STATEMENT.md`.

## Delivered

- **Browser group `a11y-browser`** (`tools/browser/a11y-check.mjs`; `scripts/run.py a11y-browser`; last line of `make browser`, so the CI job `local-reference-and-browser` runs it). axe-core **4.13.0** is pinned exactly in `tools/browser/package.json` and its lock file and injected through `page.evaluate` (the DevTools protocol, so the application's CSP is not loosened). Rule tags `wcag2a wcag2aa wcag21a wcag21aa wcag22aa`; a violation with one of those tags and impact `serious` or `critical` fails the group unless an entry of `EXCEPTIONS` matches its rule, page and every node; best-practice findings are recorded as advisory, axe's undecided items as `needs_manual_review`. Evidence: `docs/evidence/a11y-browser-tests.json` (per-page results, keyboard focus trail with outline contrast, accepted exceptions — currently none).
- **Pages scanned (43 states)** as `author`, `reviewer` and `admin` on the synthetic fixture: sign-in; portfolio; measurement; measurement setup × 3 tabs; results framework × 4 tabs; dashboards; forms; imports; change requests; period close; my work; results; reports; my account; review queue; people and access × 5 tabs; workspace settings × 6 sections; tenant lifecycle with the Workers panel; recovery contacts; initial access; authority renewal; programme, observation (with evidence panel), result and approved-report (with exports panel) record dialogs; new-programme, add-observation and review-decision dialogs; portfolio at 390 × 844.
- **Keyboard-only checks** (Tab/Enter/Escape/arrows/typing only, no pointer events): (1) author adds an observation, saves, opens and submits it for review; (2) a different reviewer filters the queue, opens the submission and approves it; (3) dialog focus moves in, cannot reach the page behind, Escape closes and returns focus to the opener; (4) tab-list arrow/Home/End movement and Enter selection; (5) skip link is the first Tab stop, visible when focused, and moves focus to `#main-content`. Every control on the path must show an outline ≥ 2 px whose contrast against the first opaque background behind it is ≥ 3:1.

Clean run (1 Oct 2026, Chromium 153, PGlite): 8 checks passed, 0 failing violations, 0 accepted exceptions.

## Accepted exceptions

None. `EXCEPTIONS` in `a11y-check.mjs` is empty; any future entry must name the rule, the page states, a target pattern matching every node and a justification, and is written to the evidence file.

## Limits

No screen reader, no browser other than Chromium 153, no 200 %/400 % zoom or reflow check beyond one 390 px state, no manual WCAG 2.2 audit, no check of the Keycloak sign-in pages or of generated HTML/CSV/PDF/XLSX/DOCX artifacts, keyboard walk-through of one flow only (not the invalid-field and stale-revision cases of FT-UX-004/AT30). After a save that reloads a list, focus falls back to the document start. Other panels still mount their status messages only when they appear. Tabs keep every tab in the Tab order and have no `aria-controls`/`tabpanel`. Details in the accessibility statement.
