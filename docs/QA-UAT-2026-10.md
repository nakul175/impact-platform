## Findings verified in code (new; not in any release note)

1. A tenant onboarded on staging has no reporting calendar, periods, workflow template or report template, and no implemented route creates them (only `specification/fixtures/seed.sql` does).
2. The onboarding access profile `apps/api/impact_api/bootstrap_profile.json` (`initial-access-v1`) predates build 0.18: 48 capabilities of implemented operations lie outside every real tenant's delegation ceiling (frameworks, targets, forms, imports, evidence, dashboards, exports, publication, audit export, privacy).
3. No implemented route issues purpose-bound grants, so `DATA_SUBJECT_REQUEST` privacy cases work only with fixture grants.
4. Observations that are not planned sources block period close (`UNPLANNED_VALUES`), and import source keys cannot be planned in advance, so importing into a planned indicator can make its period unclosable.
5. Activation of a tenant needs a second platform operator, which staging cannot create without a manual database change.
6. DEPLOYMENT-GUIDE §4 overstates the recovery-contact approver rule (the requesting operator may approve; only the owner and nominee are excluded).
