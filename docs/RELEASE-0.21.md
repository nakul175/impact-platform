## Delivered

Until this build values entered the platform one at a time: a manual observation or a form response. This increment adds bounded tabular import: a file is mapped to indicators, every row is checked before anything is written, and the accepted rows become observations that enter the existing independent review, calculation and period-close path.

**Import batches (FR-DAT-001).** An import batch (registry kind `ImportJob`, route `imports`) carries its own source in the request body: CSV text, or the base64 of an `.xlsx` file of which the first worksheet is read. The XLSX reader uses only the Python standard library (no new dependency): base64 and zip structure are checked first, the archive may hold at most 500 entries and 8 MiB uncompressed, and any XML document type declaration is refused (`FILE_UNSAFE`), so entity expansion cannot occur. Every cell is read as text, so leading zeros (`00123…`), a 20-digit identifier and a quoted comma are kept exactly; the preview shows each row's raw cells beside their interpretation. A cell holding a formula in a mapped column is quarantined (`FORMULA_NOT_PERMITTED`). Dates are never guessed: event dates are ISO 8601 with an explicit offset unless the batch declares `date_pattern` (`YYYY-MM-DD`, `DD/MM/YYYY`, `MM/DD/YYYY`, read at midnight in the period's reporting zone); `03/04/2026` without a pattern is `EVENT_AT_INVALID`. A numeric spreadsheet cell in the date column is a 1900-system serial day. Without an event column the event is the period's start.

**Mapping (FR-DAT-002).** The mapping binds source columns by header name, never position: a unit column, an optional event-date column, value columns each bound to an indicator instance with a role (VALUE, NUMERATOR, DENOMINATOR), the unit the column is stated in and optional bounds, optional dimension columns and optional explicit missing-value tokens (for example `NA` → NOT_APPLICABLE). The whole batch is refused before any row is staged when a mapped column is absent or renamed (`MAPPING_COLUMN_MISSING`; values are never shifted into another column), an indicator is outside the batch's programme, not active or not a manual COUNT/DECIMAL/RATIO/PERCENTAGE measure (`MAPPING_INDICATOR_INVALID`), roles do not match the measurement type (`MAPPING_ROLE_INVALID`), a stated unit differs from the pinned definition's unit (`MAPPING_UNIT_MISMATCH`) or a dimension is not declared by a bound definition (`MAPPING_DIMENSION_INVALID`). Unmapped columns are listed as dropped. Editing a batch discards its staged preview and returns it to Draft.

**Staging, row outcomes and quality checks (FR-DAT-004, FR-DQ-003, FR-DQ-007).** Preview (`import.preview`) parses the file, validates every data row against the mapping and the pinned indicator definitions and writes only the batch's next revision (state Previewed); no observation exists until commit. Each row is ACCEPTED, QUARANTINED with reason codes, or DUPLICATE, and the counts reconcile (`rows = accepted + quarantined + duplicate`). Blocking checks: row shape, unit key missing or malformed, event date missing, malformed or outside the period, value not a plain decimal, a COUNT that is not a non-negative integer, a value outside the mapped bounds, negative ratio components or a percentage numerator above its denominator (`INVALID_COMPONENTS`), an invalid or missing exhaustive dimension code, formulas and over-long cells. Value states follow forms: a blank cell is MISSING, a declared token keeps its state, one blank ratio component makes the value MISSING, a zero denominator is UNDEFINED — none of them is ever zero. Exact duplicate detection uses declared business keys: the same unit twice in one batch (`DUPLICATE_IN_BATCH`), the same unit, indicator and period already committed by an import (`DUPLICATE_UNIT_PERIOD`, backed by the insert-only register below), or a form observation for the same unit and indicator with an event in the period that is not rejected (`DUPLICATE_SOURCE_KEY`). The anomaly check is a warning only: a modified z-score (0.6745·(x − median)/MAD, threshold 3.5) against the indicator's 200 most recent approved PRESENT values, evaluated only with at least five values, a non-zero MAD and the previewer's TENANT-scope `observations.read`; the method, its version and the evaluated indicators are recorded on the batch, and a flag never changes or blocks a value. The staged outcome is pinned by a SHA-256 preview hash over the content digest, mapping, period, programme, date pattern, mode and every row outcome.

**Commit (FR-DAT-004, FR-DQ-002 in part).** Commit (`import.commit`, plus `observation.submit` at TENANT scope, reason `OBSERVATION_SUBMIT_REQUIRED`) takes the preview revision as `expected_revision` and the preview hash. Under the tenant lock it recomputes the outcome and refuses it when it differs (`PREVIEW_STALE`, for example after another batch committed the same unit; `PREVIEW_HASH_MISMATCH` when the supplied hash is not the staged one). An atomic batch commits nothing if any row is not accepted (`IMPORT_ATOMIC_REJECTED`); a partial batch commits exactly its accepted rows and keeps the rest on the batch as its manifest. A batch with warnings commits only with `accept_warnings: true`, recorded on the batch. For each accepted row and bound indicator one observation is written in the reserved `IMPORT` namespace with source key `<batch id>/<unit key>/<indicator id>`, `source_version` the committed preview revision, `captured_at` the batch's receipt time and `capture_zone` the period's reporting zone, and submitted into the existing independent observation review — the same transaction as the batch's Committed revision and its register rows, so a batch is applied completely or not at all. Every natural author of the batch (whoever created or edited it) and the committer become authors of each observation, so none of them can approve it (`INDEPENDENCE_REQUIRED`). Cancel (`import.cancel`, reason required) ends a Draft or Previewed batch; nothing was committed, so nothing is rolled back. A Committed or Cancelled batch cannot be edited, previewed or committed again.

**Reserved namespace.** `IMPORT` is reserved like `FORM`: a direct observation create or patch using it is refused (`SOURCE_NAMESPACE_RESERVED`).

**UI.** An Imports area: choose programme and period, load a CSV or XLSX file (the client refuses a file whose encoded content exceeds the bound), name the unit and optional date column, map value columns to indicators with role and unit, choose atomic or partial mode, save a draft, preview (row table with raw cells, interpretation, reasons and warnings), and commit — with an explicit acknowledgement checkbox when warnings exist. Buttons are gated by `/me/access` (commit needs `import.commit` and `observation.submit`); mutation operation identifiers are kept per action and payload so a retry returns the original receipt.

## Limits

- Bounds: the content field is at most 196,608 characters (192 KiB) so the whole command fits the unchanged 256 KiB request cap — about 144 KiB of XLSX after base64; at most 500 data rows, 40 columns, 20 mapped value columns, 10 dimension columns, 1,000 characters per mapped cell and 500 observations per batch (rows × bound indicators). Preview and commit run synchronously in the request; there is no worker job class, no upload session and no object store (v0.22).
- Not implemented: reusable, versioned and reviewed mapping objects (the mapping lives in the batch), transformations, encoding/delimiter/sheet/header-row choice (UTF-8 text, comma, first sheet, first row), locale-aware numbers (plain `.` decimals only), keyed update and controlled replacement (mode APPEND only; FR-DAT-003), schema-drift review across recurring loads (FR-DAT-007), separate retention of the raw file beyond the batch revision (FR-DAT-005), a quality rule catalogue (FR-DQ-001), QualityIssue objects with owner, exception, correction and revalidation (FR-DQ-002/005; warnings are accepted per batch, not by a recorded exception with authority and expiry), reconciliation checks (FR-DQ-004), fuzzy matching and merge (FR-DQ-003), anomaly review states (FR-DQ-007).
- Corrections: imported observations cannot be patched (the namespace is reserved), so a returned or rejected imported value is corrected through the approved-value amendment path after approval, as for forms. A unit committed once for an indicator and period stays in the register even if its observation is later rejected, so it cannot be re-imported for that period.
- Collection plans cannot name import obligations in advance (the source key contains the batch identifier), so imported values are unplanned contributions when a plan exists.
- Duplicate detection against forms covers form observations keyed `<unit>/<indicator>`; manual observations are not compared. The anomaly history ignores period and seasonality.
- The batch revision stores the full source and row outcomes; preview and commit each add a revision, so a batch costs about three copies of its content.
- No browser check covers the Imports area yet. Native evidence for the register fence is a new native-only test that this branch did not run locally (shared two-CPU machine); CI's native job runs it.
