## Delivered

Until this build an approved report package could be exported only as HTML and CSV, rendered synchronously by the API. This increment adds PDF, XLSX and DOCX renderings of the same frozen package, produced by the worker as its first executed job class, stored immutably, downloadable through a mediated and logged route, and deliverable to named recipients through the existing controlled-publication flow.

**Rendering (FR-RPT-005, FR-RPT-003).** `export_render.py` builds one document model from the immutable revisions a package binds — the approved report revision, its approved template revision, the locked snapshot revision and the OFFICIAL result revisions named by the numeric bindings — and renders it with reportlab (PDF), openpyxl (XLSX) and python-docx (DOCX). Every number is the result's stored `displayed_value` and unit exactly as the HTML and CSV artifacts print them: nothing is recalculated, summed or re-rounded. The PDF and DOCX carry the banner, title, each section's heading and narrative with bound values in bold, a metric table per section and the footer (report, revision, snapshot, lock time, reconciliation SHA-256, rendering version). The XLSX carries a "Bound values" sheet with exactly the CSV's columns and rows and a "Package" sheet with the narrative and identifiers; every cell is stored as text, so a displayed number is never converted or re-rounded and a value beginning with `=` is never a formula. Output is byte-for-byte deterministic: metadata comes from the package (the snapshot's lock time, the report identity), never from the clock; ZIP containers are rewritten with a fixed entry time and order; the PDF is produced in reportlab's invariant mode. `RENDERER_VERSION` (`exports-1`) is recorded with every job and artifact separately from the content version. The PDF uses the standard Helvetica faces (Windows-1252); a package containing a glyph they cannot draw is refused (`RENDER_GLYPH_UNSUPPORTED`, permanent) instead of being rendered with missing characters; XLSX and DOCX carry Unicode text.

**Request, cancellation and status.** `POST reports/{id}/actions/export` (`report.export`, TENANT scope, `expected_revision` = the approved head) is an ordinary domain command: it rechecks the frozen package exactly as the HTML export does (approved report, binding present, reconciliation digest unchanged, every bound result readable by the requester) and, in the same transaction as its receipt, audit event and outbox event, writes one `impact.job` row (job class `REPORT_EXPORT`, state Queued, the pinned package in `input_manifest`) and one `report_export` row (pinned report revision, format, rendering version, reconciliation digest, due now on the database clock). The receipt names the report revision and carries `job_id`; an exact retry returns it, a changed payload under the same operation is `CONFLICT_OPERATION`. A second open or succeeded export of the same revision, format and rendering version is refused (`EXPORT_ALREADY_REQUESTED`); at most 20 unfinished export jobs per tenant (`EXPORT_QUEUE_LIMIT`, 429). `POST reports/{id}/actions/cancel-export` records a cancellation request only; the worker's existing cancellation pass cancels a job that has not started (job_item `cancellation` CANCELLED_BEFORE_START) and never claims one with a request; a started job is not cancelled (NOT_CANCELLED_STARTED), except that a request made while an attempt fails is honoured before the retry (`BETWEEN_ATTEMPTS`). `GET reports/{id}/exports` lists the 100 newest exports with state, attempts, error class, cancellation outcome, SHA-256 and size.

**Worker execution (job class REPORT_EXPORT).** Per Active tenant named by the new definer `impact.worker_export_tenants(at)`, the worker claims due jobs under the tenant advisory lock with the outbox discipline: Queued (no cancellation request, due) or Running with an expired lease becomes Running with `lease_generation + 1`, a 60-second lease on the database clock, the lease owner and one more attempt (`FOR UPDATE SKIP LOCKED`, at most four per batch). Per job, a transaction renews the lease (fenced on owner and generation and only while the lease is live) and reads the pinned package; the connection is closed; the document is rendered outside any transaction; a fenced outcome transaction either stores the artifact and marks the job Succeeded (job_item `artifact` CREATED), requeues it with the delivery backoff (`min(3600, 30·2^(attempts-1))·U[0.5,1)` s), or marks it Failed with an error class only (job_item `artifact` FAILED). A stale holder's renewal and outcome match no row, so one job yields at most one artifact. Six attempts (the worker's `max_attempts`) or a permanent class (`RENDER_FAILED`, `RENDER_GLYPH_UNSUPPORTED`, `PACKAGE_BINDING_CHANGED`, `PACKAGE_REVISION_MISSING`, `PACKAGE_CONTENT_RESTRICTED`, `RESULT_NOT_OFFICIAL`, `EXPORT_ARTIFACT_LIMIT`, `PREPARE_DEFECT`) end in Failed; a lease that expires at the attempt limit ends in Failed `LEASE_EXPIRED`. Privacy-restricted package content is never reconstructed: the job fails. SIGTERM releases claimed-but-unstarted export jobs with their attempt restored. Outbox delivery behaviour is unchanged.

**Storage.** Artifact bytes live in the database (`report_export_artifact.body`, at most 10 MiB), as the HTML and CSV publication artifacts do; SHA-256, media type, rendering version and the lease generation that produced them are recorded. The table is insert-only for the worker and read-only for the application; nothing updates or deletes an artifact, and a download whose bytes no longer match their recorded digest is refused (`EXPORT_ARTIFACT_INTEGRITY`, 503). The object store being built in parallel is not used; moving the bytes there is a follow-up.

**Download and delivery (FR-RPT-007, FR-RPT-009).** `GET reports/{id}/exports/{job}/download` (`report.export`) returns the bytes as an attachment with the SHA-256 as ETag and logs an `INTERNAL_DOWNLOAD` row in `report_export_access`. A disclosure request may name `export_formats`; the server pins each to the exact succeeded artifact of the disclosed report revision (`export_artifacts`: format, job, SHA-256 — server-owned; a request that supplies it is refused by the closed schema) before independent review, so the reviewer approves exact bytes; a format without an artifact is refused (`EXPORT_ARTIFACT_REQUIRED`). Approval and publication re-verify the pinned artifacts; publication binds them in `report_publication_export`, never re-pointed. A named, active recipient with the download right then downloads `publications/{id}/download.pdf|.xlsx|.docx` (`publication.download`), logged as `RECIPIENT_DOWNLOAD`; anyone else, a recipient without the download right, an expired or withdrawn publication, an unbound format and another tenant all receive the same 404. Adding a format for an audience already served is a new disclosure decision, not a change to the published one; a wider audience remains a new disclosure. Withdrawal closes access and never deletes or recalls artifacts.

**UI.** An approved report's detail shows "Rendered exports" to holders of `report.export`: request PDF, XLSX or DOCX, see status (refreshed while work is open), cancel a queued export and download a succeeded one; operation identifiers are kept per action and payload until success. The disclosure request dialog offers the rendered formats to include.

## Limits

- Not implemented: charts and figures, page-break and caveat validation, accessibility conformance (the PDF is not tagged; DOCX headings and tables are structural but unaudited), fonts beyond Windows-1252 in PDF, slide and donor formats (FR-RPT-006), scheduled distribution, notices and email of artifacts (FR-RPT-008), supersession notices, an artifact access expiry separate from the disclosure's, an operator re-queue for Failed exports.
- PDF metadata dates are reportlab's fixed invariant date (2000-01-01), not the snapshot lock time; the lock time is printed in the document and set in XLSX and DOCX properties.
- VF-PER-005 is not measured: no 100,000-row export, 50-page report, twenty-chart report, p95 or mixed-load run exists. Request acknowledgement is a single synchronous transaction; progress is the job state only (no percentage); cancellation works before start only.
- One open or succeeded export per (revision, format, rendering version) is enforced by the service under the tenant lock, not by a constraint; the open-export limit is per tenant (20), not per requester.
- Bytes are stored in PostgreSQL (10 MiB per artifact); there is no object store, retention or purge, and the worker heartbeat's counters do not include exports.
- The worker reads the pinned revisions through its own login (SELECT on `object_revision` and `report_package_binding`), not through a requester's grants; authorisation is checked when the export is requested and when it is downloaded.
- On PGlite every transaction is serialised; concurrent claims are exercised only by the native-only test. Native evidence is single-node PostgreSQL without a pooler. Nothing was deployed.
