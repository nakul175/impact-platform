## Integration changes (beyond merging)

1. **Defect fixed — late values in a locked period with two calendars** (reported by #68, not fixed there). `PeriodGovernance.assert_source_mutable` looked only at the latest-starting period containing an event, tenant-wide; with a second reporting calendar (possible since v0.26a) an event inside a programme's locked quarter also lies in the other calendar's month, Open for that programme by default, so a late observation could be submitted into a locked period. It now checks every period that contains the event and refuses unless each is Open (or RestatementOpen with a restatement permission for that source). Regression test `qualification/test_import.py::test_a_locked_period_refuses_late_values_when_another_calendar_overlaps_it` (two 2024 calendars, a locked quarter, an Open month) fails without the fix and passes with it. #79 fixed the same defect on the imports branch during the integration by looking the period up on the programme's own calendar only; at the second merge of #68 the broader check was kept, because it refuses in every case that lookup refuses and also protects a period the programme closed outside its current calendar (period close does not require calendar membership), while a period the programme never closed is Open for it and never blocks. #79's test — `test_period_governance.py::test_close_creates_immutable_snapshot_and_official_results` now creates an overlapping 2026 month before the late submission and still expects 409 — was kept beside the integration's.
2. **Test defect fixed — order-dependent sweep lookup in #74's tests.** In the full PGlite gate (alphabetical order) `test_retention.py` runs before `test_security_privacy.py` and its backoff test leaves a sweep whose `next_attempt_at` lies hours ahead on a skewed worker clock, so `sweep_jobs(live)[-1]` named that sweep and two #74 tests failed (`KeyError` on the proof). The integration first added a helper that identified the sweep a pass created by identity; at the second merge of #74 it was replaced by #74's own fix of the same problem (5c0c1b6: `test_retention.sweep_ids()` and `sweep_created_since()`, which also cover `test_retention.py`'s own call sites). Both file orders pass. No assertion was weakened.
3. **Access gate (#77) and the new capability families.** `areaCapabilities` in `main.tsx` lists People & access for holders of `access-denials.*`, `retention.*`, `retention-policies.*`, `retention-policy.*` and `retention-holds.*` (#74's panels render there). No slice added a navigation area: the portfolio is a tab inside Dashboards (#71), rounds and assignments have no screen (#73).
4. **`make unit`** gains `test_status_alerts_unit.py` (#76, 17; its note counted it but the target was not edited) and `test_security_privacy.py` (#74: 3 pure tests run, 6 live tests skip without a database).
5. **Upgrade check from the deployed schema.** `scripts/native_upgrade_check.py` upgrades from `LATEST - 1` unless `IMPACT_UPGRADE_BASELINE` names an earlier schema (21 or later); the CI native job sets **28**, the schema staging runs, so the four migrations are rehearsed together on a populated database. A platform operator row is now present at the baseline (0029 alters `platform_operator`), and the 0029–0032 columns and tables, the operator row and the legacy assignment row are verified after the upgrade.
6. **Training video (#67)** was written against build 0.26.0: its tenant-change steps and landing check now follow #77's dialog and waiting page (`training-video.mjs`); `TRAINING-VIDEO.md` updated. See "Qualification" below for what was run.
7. **Regenerated:** `packages/contracts/*` and `docs/API-INVENTORY.md` (`scripts/build_contracts.py`, `scripts/export_implemented_api.py`; `augment_reference` still runs last), `bootstrap_profile.json` (`scripts/build_access_profile.py`), versions in `VERSION.json`, `apps/web/package.json` and its lock.
