# Build 0.39 disclose commercial relationships on every listing (US-DC-04)

9 October 2026 · Local candidate on branch `sprint-1/us-dc-04` (from `sprint-1/us-mp-03`), committed locally only (not pushed, merged or deployed) · build 0.39.0 · domain API 1.28.0 · platform API 1.11.0 (unchanged) · schema 43 (migration 0043) · 267 implemented domain operations (unchanged).

Every tool listing in the AI enablement directory now states whether Imprana has a known commercial relationship with the listing's provider, so an Executive Director can judge the directory's neutrality. Today no relationship is known for any of the eight listings, and each says so ("No commercial relationship known"); nothing is invented. A listing without a valid disclosure is never shown: the directory is not served at all. Saved plans keep the disclosure that was current when they were saved, and plans saved before this build still open. Nothing here is accepted: US-DC-04 is "In review" in the backlog, hosted CI has not run, and the eight declarations are an editorial draft that no advisor has reviewed.

## Delivered behaviour

1. **Disclosure on every listing.** Each listing of `apps/api/impact_api/ai_solutions_catalog.py` carries `commercial_disclosure` `{status, relationship_types, statement, declared_on}`. `status` is `NONE_KNOWN` (no relationship type) or `DISCLOSED` (at least one of `referral_fee`, `revenue_share`, `reseller`, `sponsorship`, `ownership`, no repeats); both need a statement (1–1,000 characters, not blank) and a calendar date. All eight listings are `NONE_KNOWN`, declared 2026-10-09 (`DISCLOSURES_DECLARED_ON`), with the statement "Imprana editorial declaration, pending advisor review: no referral fee, revenue share, reseller, sponsorship or ownership relationship between Imprana and <provider> is known. The platform has no registered marketplace vendors." (the catalogue's `marketplace_status.vendors` is empty). The wording is "is known", never "does not exist". The directory explanation gains one sentence saying each listing states any relationship Imprana editorial knows of.
2. **Fail closed.** `solutions_catalog()` validates every listing before returning: plain rules (`validate_disclosure`) and the closed JSON schema (`catalog_schema()`, which is the published contract). A missing or invalid disclosure, including `DISCLOSED` without a type or a statement, raises `SolutionsCatalogInvalid`; `GET …/ai-enablement/solutions` then answers 503 `SERVICE_UNAVAILABLE` / `AI_SOLUTIONS_CATALOG_INVALID` and serves nothing, and every plan save is refused with the same reason and rolls back (no revision, archive, audit or receipt). The API and the other AI enablement reads keep working. The listing builder never adds a disclosure by default, so a new listing without one stops the directory.
3. **Edition `.2` of the directory.** `CONTENT_VERSION` becomes `nonprofit-solutions-2026-10-05.2`; `CHECKED_ON` stays 2026-10-05 because no source fact was re-checked. Plans saved before report their solutions edition as `STALE`, as for any earlier edition.
4. **Archive edition v2 with the v1 reader kept.** Saved plan revisions archive their guidance in `nonprofit-ai-guidance-v2` (`apps/api/impact_api/ai_content_schema_v2.json`, frozen): identical to v1 except that every solutions listing requires `commercial_disclosure`. `ai_content_schema_v1.json` is byte-identical (pinned by SHA-256 in a unit test) and still reads every v1 archive. `ai_content_archives.py` keeps one reader per edition (`EDITIONS`, `READERS`); a snapshot is read only when the row's label and the hashed payload's label agree and the payload satisfies that edition's reader, otherwise 503 `AI_GUIDANCE_UNREADABLE`. New saves capture v2; no v1 row is relabelled or backfilled. A practice guide archived under v1 is reused in a v2 bundle only when identical (its schema is unchanged).
5. **Web.** A shared `AIDisclosureLabel` (`AIToolComparison.tsx`) shows "No commercial relationship known", or "Commercial relationship disclosed: <types>", with the statement and "Declared <date>." It is a `role="note"` named "Commercial disclosure for <tool>", so screen readers announce it with the tool's name. It appears on every tool card (`AIAdoptionWorkspace.tsx`), in a "Commercial disclosure" row of every comparison column, and on every listing of a saved plan's archived tool directory (`AIGuidanceArchive.tsx`), which also names the archive edition; a v1 archive says "Commercial disclosure not recorded" and that the revision was saved before disclosures were recorded. The invented tools of the public walkthrough carry a `NONE_KNOWN` disclosure stating that their providers do not exist. Styles use the existing tokens (`ai-enablement.css`).

## Contract and persistence

- **`AISolutionsCatalog`** changes from an open object with five required keys to the closed schema `catalog_schema()`: the edition-1 listing shape plus the required disclosure (two closed variants by `status`). No route, capability, role, assurance or audit change; `GET …/ai-enablement/solutions` keeps `ai.enablement.read`. Domain API 1.28.0; `access-policy.json` changes only its version.
- **`AIAdoptionPlanGuidance`** (guidance read) becomes one closed variant per archive edition (`snapshot_schema_version` `nonprofit-ai-guidance-v1` with the `AIArchived*V1` payloads, or `nonprofit-ai-guidance-v2` with `AIArchivedSolutionsV2` and the unchanged catalog and practice payloads), plus the unavailable variant (all labels null). Identical components reuse their earlier schema name.
- **Plan export.** The export document's `guidance` member uses the same variants with inline payloads. The package stays `nonprofit-ai-plan-export-v1` and its frozen plan projection is unchanged; exports issued before 0.39.0 (v1 guidance) replay byte for byte, and exports of plans saved from now on carry the disclosures inside their archived guidance.
- **Migration `0043_ai_guidance_v2.sql`** (SHA-256 `e6477be6b87b706af649ed63e93173c9ba870d8d48b970c0d356c0584ed5531b`, recorded in the [data dictionary](current/CURRENT-DATA-DICTIONARY.md)): drops `ai_content_snapshot_schema_version_check` (the name PostgreSQL gave 0037's column check) and re-creates it as `schema_version IN ('nonprofit-ai-guidance-v1','nonprofit-ai-guidance-v2')`, which validates every existing row. No table, column, grant, role, RLS policy, trigger or function change; snapshots and bindings stay insert-only and tenant-fenced. Migrations 0001–0042 are byte-identical.

## Limits

- **The declarations are an editorial draft.** The eight `NONE_KNOWN` statements were written by the implementing engineer for Imprana editorial from what the repository shows (no marketplace vendor, no fee or placement code); no advisor has reviewed them and no evidence beyond the date is recorded. Whether "none known" is true is not verified by the platform (threat TH36, gap recorded).
- A disclosure changes only through a code change with a new `CONTENT_VERSION`; there is no editorial screen or approval workflow, and nothing checks a declaration against contracts or payments.
- No `DISCLOSED` listing exists, so the disclosed label is qualified in the browser on a modified response only; the server rules for it are unit-tested.
- Listing order and use-case mappings remain editorial and are not governed by a placement policy (FR-NPA-018 target).
- A consumer that validates plan exports against the document schema published before 0.39.0 would reject an export whose guidance is v2; the package label is unchanged (see deviation 2).
- Revisions saved before this build show no disclosure: the archive has none, and none is reconstructed from today's directory.

## Deviations from the story card

1. "The catalogue does not load": an invalid listing makes the directory read answer 503 and refuses plan saves; the API process itself still starts, so unrelated areas stay available. The unit check fails as the card asks.
2. "Check the plan export": the export package keeps `nonprofit-ai-plan-export-v1`. Its `guidance` member was always the archive's own shape and is labelled by `snapshot_schema_version`, so it now admits v1 or v2 guidance; no export migration was needed (0040's `guidance_schema_version` column has no edition check). Bumping the package to v2 instead would need another CHECK change in 0043 and a second document validator; the owner may prefer that.
3. Beyond the card: the guidance read contract is now one closed variant per edition (label bound to payload shape) instead of one object admitting any label; a v1-labelled archive with v2-shaped content is refused.
4. The Executive Director persona maps to OWNER, which holds no AI enablement capability; the browser check uses the tenant administrator (TENANT_ADMIN, "where the owner delegates administration" in the persona map). The PGlite tests read as the fixture reviewer and administrator.
5. Beyond the card: `scripts/native_upgrade_check.py` (shared with the restore drill) could not read a migration name containing a digit, which the story's own `0043_ai_guidance_v2.sql` has; its parser now accepts digits (guarded by a new `test_version_unit.py` test), and the upgrade check now also inserts one v1-labelled guidance snapshot when the baseline already has 0037 and verifies it after the upgrade, so 0043 runs on a populated table.
