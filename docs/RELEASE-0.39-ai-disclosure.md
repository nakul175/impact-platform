# Build 0.39 disclose commercial relationships on every listing (US-DC-04)

9 October 2026 · Local candidate on branch `sprint-1/us-dc-04` (from `sprint-1/us-mp-03`), committed locally only (not pushed, merged or deployed) · build 0.39.0 · domain API 1.28.0 · platform API 1.11.0 (unchanged) · schema 43 (migration 0043) · 267 implemented domain operations (unchanged).

Every tool listing in the AI enablement directory now states whether Imprana has a known commercial relationship with the listing's provider, so an Executive Director can judge the directory's neutrality. Today no relationship is known for any of the eight listings, and each says so ("No commercial relationship known"); nothing is invented, and each says it is a draft pending Imprana editorial confirmation. A listing without a valid disclosure is never shown: the directory is not served at all. Saved plans keep the disclosure that was current when they were saved, and plans saved before this build still open. Nothing here is accepted: US-DC-04 is "In review" in the backlog, hosted CI has not run, and the eight disclosures are drafts prepared for Imprana editorial review that nobody has confirmed. Plan copies whose archived guidance carries disclosures are issued as a new package edition, `nonprofit-ai-plan-export-v2`; copies of older plans keep the published v1 package byte for byte.

## Delivered behaviour

1. **Disclosure on every listing.** Each listing of `apps/api/impact_api/ai_solutions_catalog.py` carries `commercial_disclosure` `{status, relationship_types, statement, declared_on, editorial_confirmation}`. `status` is `NONE_KNOWN` (no relationship type) or `DISCLOSED` (at least one of `referral_fee`, `revenue_share`, `reseller`, `sponsorship`, `ownership`, no repeats); both need a statement (1–1,000 characters, not blank), the calendar date the disclosure was prepared and `editorial_confirmation` (`PENDING`: a draft prepared for Imprana editorial review; `CONFIRMED`: confirmed by Imprana editorial). All eight listings are `NONE_KNOWN`, `PENDING`, prepared 2026-10-09 (`DISCLOSURES_DECLARED_ON`), with the statement "Draft declaration prepared for Imprana editorial review; not yet confirmed. No referral fee, revenue share, reseller, sponsorship or ownership relationship between Imprana and <provider> is known. The platform has no registered marketplace vendors." (the catalogue's `marketplace_status.vendors` is empty). The wording is "is known", never "does not exist", and no statement claims that Imprana editorial declared anything. The directory explanation gains one sentence saying each listing states any known relationship and that the disclosures are drafts pending Imprana editorial confirmation. `category` is closed to the six published categories.
2. **Fail closed.** `solutions_catalog()` validates every listing before returning: plain rules (`validate_disclosure`) and the closed JSON schema (`catalog_schema()`, which is the published contract). A missing or invalid disclosure, including `DISCLOSED` without a type or a statement, raises `SolutionsCatalogInvalid`; `GET …/ai-enablement/solutions` then answers 503 `SERVICE_UNAVAILABLE` / `AI_SOLUTIONS_CATALOG_INVALID` and serves nothing, and every plan save is refused with the same reason and rolls back (no revision, archive, audit or receipt). The API and the other AI enablement reads keep working. The listing builder never adds a disclosure by default, so a new listing without one stops the directory.
3. **Edition `.2` of the directory.** `CONTENT_VERSION` becomes `nonprofit-solutions-2026-10-05.2`; `CHECKED_ON` stays 2026-10-05 because no source fact was re-checked. Plans saved before report their solutions edition as `STALE`, as for any earlier edition.
4. **Archive edition v2 with the v1 reader kept.** Saved plan revisions archive their guidance in `nonprofit-ai-guidance-v2` (`apps/api/impact_api/ai_content_schema_v2.json`, frozen): identical to v1 except that every solutions listing requires `commercial_disclosure` and its `category` is one of the published categories (the file was regenerated once during review, before any v2 archive existed outside a test database). `ai_content_schema_v1.json` is byte-identical (pinned by SHA-256 in a unit test) and still reads every v1 archive. `ai_content_archives.py` keeps one reader per edition (`EDITIONS`, `READERS`); a snapshot is read only when the row's label and the hashed payload's label agree and the payload satisfies that edition's reader, otherwise 503 `AI_GUIDANCE_UNREADABLE`. New saves capture v2; no v1 row is relabelled or backfilled. A practice guide archived under v1 is reused in a v2 bundle only when identical (its schema is unchanged).
5. **Plan copies.** The package label follows the archived guidance edition and is never taken from a request: v2 guidance gives `nonprofit-ai-plan-export-v2`, v1 or no archive gives `nonprofit-ai-plan-export-v1`, whose document is exactly the shape published at build 0.38.0 (a v1-guidance copy is byte-identical to what 0.38.0 rendered). Issue and replay validate a copy with the schema of the label it names and refuse a label that does not match its guidance edition. The web adapter (`AIPlanExportAdapter.ts`) accepts each label only with its own guidance edition and a document label equal to the manifest's.
6. **Web.** A shared `AIDisclosureLabel` (`AIToolComparison.tsx`) shows "No commercial relationship known", or "Commercial relationship disclosed: <types>", followed by "· pending editorial confirmation" while the disclosure is `PENDING`, with the statement and "Declared <date>." It is a `role="note"` named "Commercial disclosure for <tool>", so screen readers announce it with the tool's name. It appears on every tool card (`AIAdoptionWorkspace.tsx`), in a "Commercial disclosure" row of every comparison column, and on every listing of a saved plan's archived tool directory (`AIGuidanceArchive.tsx`), which also names the archive edition; a v1 archive says "Commercial disclosure not recorded" and that the revision was saved before disclosures were recorded. The invented tools of the public walkthrough carry a `NONE_KNOWN` disclosure stating that their providers do not exist (no editorial claim, so no confirmation status). Styles use the existing tokens (`ai-enablement.css`).

## Limits

- **The disclosures are drafts.** The eight `NONE_KNOWN` statements were prepared by the implementing engineer for Imprana editorial review from what the repository shows (no marketplace vendor, no fee or placement code); they are `PENDING`, nobody has confirmed them, and no evidence beyond the date is recorded. `CONFIRMED` records no confirmer yet. Whether "none known" is true is not verified by the platform (threat TH36, gap recorded).
- A disclosure changes only through a code change with a new `CONTENT_VERSION`; there is no editorial screen or approval workflow, and nothing checks a declaration against contracts or payments.
- No `DISCLOSED` listing exists, so the disclosed label is qualified in the browser on a modified response only; the server rules for it are unit-tested.
- Listing order and use-case mappings remain editorial and are not governed by a placement policy (FR-NPA-018 target).
- A consumer that understands only `nonprofit-ai-plan-export-v1` receives v1 copies exactly as before; copies of plans saved from this build are v2, which such a consumer must learn to read.
- Revisions saved before this build show no disclosure: the archive has none, and none is reconstructed from today's directory.

## Deviations from the story card

1. "The catalogue does not load": an invalid listing makes the directory read answer 503 and refuses plan saves; the API process itself still starts, so unrelated areas stay available. The unit check fails as the card asks.
2. "Check the plan export": the first commit kept one package label for both guidance editions; the independent review showed a v2-guidance copy failed the published v1 schema, and the owner decided that copies carrying v2 guidance are `nonprofit-ai-plan-export-v2` (second commit; 0043 also widens 0040's package check).
3. Beyond the card: the guidance read contract is now one closed variant per edition (label bound to payload shape) instead of one object admitting any label; a v1-labelled archive with v2-shaped content is refused.
4. The Executive Director persona now maps to TENANT_ADMIN for working in the platform (owner decision after review; `docs/agile/PERSONA-ROLE-MAP.md`: OWNER holds custody without data access, and applies to custody actions only). The browser check signs in as the tenant administrator; the PGlite tests read as the fixture reviewer and administrator.
5. Beyond the card: `scripts/native_upgrade_check.py` (shared with the restore drill) could not read a migration name containing a digit, which the story's own `0043_ai_guidance_v2.sql` has; its parser now accepts digits (guarded by a new `test_version_unit.py` test), and the upgrade check now inserts one v1-labelled guidance snapshot as soon as the schema has 0037 (stopping the upgrade at 37 when the baseline is older, as the CI's 33 is) and compares the full definitions of both re-created checks with the definitions the same server renders for exactly v1 and v2.
6. Beyond the card (review): `editorial_confirmation` is a fifth disclosure field, so the label can say "pending editorial confirmation" from the data rather than from wording.
