## A. TolaData parity map

**Method.** TolaData's own advertised capabilities grouped into 20 areas; Built = 1, Partial = 0.5, Missing = 0. "Built" means a bounded, tested subset exists — nothing is accepted (the requirement ledger stays the authority). Assessed on 2 October 2026 against build 0.26.0 and re-scored on 3 October 2026 for build 0.27.0 from the merged release notes and tests only; a status moves only where a named test or release note justifies it.

**Result.** Build 0.26.0: 6 built, 4 partial, 10 missing → **8.0 / 20 = 40 %**. Build 0.27.0: 6 built, 5 partial, 9 missing → **8.5 / 20 = 42.5 %**. One row moved (11, portfolio aggregation: Missing → Partial); several Built and Partial rows gained depth without changing status.

## B. Ready-to-run slices

Status against what PRs #68–#77 delivered: **NOT STARTED**, **PARTLY COVERED BY #nn** (what remains is the slice) or **DONE**. Every slice lists scope, must-have tests and traps. Every slice that adds a table needs a migration (placeholder `0033_<topic>.sql`), real-role RLS negative tests (`qualification/test_native_roles.py` pattern) and, for anything the worker touches, explicit grants plus an update of `test_worker.py`'s kept and revoked sets.

1. **KoboToolbox auto-pull connector — NOT STARTED.** TolaData's signature integration. Governed connection per tenant (provider KOBO; adapter interface ready for ONA); base URL allow-list (`kf.kobotoolbox.org`, `eu.kobotoolbox.org`, configured hosts; https only; reject IP literals and private ranges; no redirects — SSRF, threat TH11); API token sealed (AES-256-GCM, key derived from the delivery keyring with its own context; never returned, logged, receipted or audited); auto-pull rules per indicator instance (form uid, value/numerator/denominator/count mapping, unit key field, period from a date field or `_submission_time`, filter, disaggregation mapping), independently approved before running; worker job class `CONNECTOR_SYNC` leased like REPORT_EXPORT, HTTP outside transactions, watermark and paging, observations in a reserved `KOBO` namespace keyed `<asset uid>/<_uuid>/<indicator>`, submitted into review, rule authors copied as authors; quarantine with reason codes; sync-run records; an Integrations screen. Tests with synthetic Kobo API v2 payloads only (the sandbox and CI cannot reach Kobo; the staging server can). Trap: the worker writing observations runs into the same authorship and grant question #68 recorded for the asynchronous import (RELEASE-0.27-imports.md "Design for the asynchronous commit") — decide the executor model first.
2. **Portfolio aggregation, saved views, governed data export — PARTLY COVERED BY #71.** Delivered: `GET indicator-definitions/{id}/portfolio?period_id=` (one definition across visible programmes, pooled totals per definition revision for SUM/COUNT/POOLED_RATIO from stored components, withheld when scope or official values are incomplete) and dashboard drill-down to source observations (`GET indicator-instances/{id}/dashboard-sources`). Remaining: a tenant-wide portfolio listing (all definitions with instances), coverage UNAVAILABLE propagation to totals, personal and shared saved views (sharing never grants data access), filters that state when they do not apply (FR-ANA-002), CSV/XLSX export of views and of raw observations/results under a separate export capability with a context sheet, a formula-injection guard and audit; MEAN/MEDIAN/LAST_VALID/MIN/MAX stay non-poolable. Tests: hidden-source withholding, cross-version refusal, export capability separate from read, deterministic bytes.
3. **Activities and workplans — NOT STARTED.** Activities linked to framework ACTIVITY/OUTPUT nodes: owner, dates, status, explicit progress, milestones, finish-to-start dependencies (no cycles); workplan baseline independently approved into an insert-only register; changes after baseline as superseding drafts with a reason; inline-SVG timeline with a text alternative; overdue items in My work; owner notices through `WorkCenter.notify`. #73's assignments are collection tasks and are not a substitute.
4. **Budget tracking (planned versus actual, not accounting) — NOT STARTED; owner decision needed.** Finance is Release 3 under SD-01; this pulls a bounded subset forward only if the owner agrees. Single programme currency, no FX; budget lines with optional phasing; baseline independently approved; expenditures entered and approved by different people; reversing entries, never edits; budget versus actual with variance and burn rate (UNDEFINED for a zero budget); pending spend shown separately; CSV/XLSX export under an export capability.
5. **Indicator library, standard mappings, logframe export — NOT STARTED.** Tenant library of approved, versioned definition templates with mappings to external code lists (synthetic example lists only); adopt into a programme as a new definition draft with provenance; newer library versions never change adopted definitions; logframe matrix export (CSV/XLSX, deterministic bytes, export capability, audit) in its own module; #70's relationships and assumptions belong in the export.
6. **Charts in reports and Unicode PDF — PARTLY COVERED BY #71.** Delivered: bar charts of a section's own OFFICIAL bindings (optionally beside the pinned target) reconciled into the frozen package, inline SVG with `<title>`, `<desc>` and a data table in HTML, vector drawing in PDF, tables in XLSX/DOCX, byte-deterministic per format (`test_report_charts.py`). Remaining: an embedded OFL font for non-Latin text in the PDF (Devanagari, accented Latin — today any glyph outside Windows-1252 fails the export job permanently), template-level `required_chart_codes`, trend charts across periods (several snapshots), other chart kinds, an accessibility check of the PDF.
7. **Discussions on records — NOT STARTED.** Threads on any record the commenter can read; hidden and missing records both 404 with no title leakage; a separate write capability; edits as revisions, resolve/reopen, retract with audit; @mentions validated (a member without read access is refused without leaking); commenting never counts as authorship for independence.
8. **Asynchronous import commit and re-import after rejection — PARTLY COVERED BY #68.** #68 resolved acceptance gap A5 (plannable IMPORT keys `<unit>/<indicator>/<period>`) but did not build the asynchronous commit; its note explains why a worker job class on `impact_worker` would amount to a second application role and records a design with an **import executor process on an `impact_app`-member login** (claim, rebuild the committer's context, re-run the commit under a fenced lease, closed error classes). Remaining: that executor (or an owner-approved alternative), batches above a threshold queued with a receipt, UI states Queued/Running/Committed/Failed, and re-import of a unit whose observation was rejected without UPDATE or DELETE of insert-only rows (today a committed unit stays in `import_unit_register` even if its observation is rejected). Keep PREVIEW_STALE semantics.
9. **Mobile web forms with an offline queue (PWA) — NOT STARTED.** Phone-first form filler; a manifest and a same-origin service worker caching only the app shell and the user's submittable form definitions (never protected API reads); an IndexedDB queue keyed by an operation ID fixed at draft start (exact-retry semantics), replay on reconnect, per-item outcome (submitted / quarantined on a superseded version / refused); queue cleared on sign-out after a warning; CSP `worker-src 'self'` and `manifest-src 'self'`. Browser check with `context.setOffline`. #73's language versions and assignments should be honoured by the filler.
10. **Multi-language UI (English, French, German first) — NOT STARTED.** Cross-cutting: it touches every screen, so run it alone, not in parallel with UI slices. Message catalogue, locale switch in preferences, server error messages keyed by reason code, date and number formatting per locale (display only; stored decimals unchanged). #73's form language versions are a separate, content-level feature.
11. **Google Sheets/Drive import and export — NOT STARTED; owner decision needed** (a Google Cloud project and an OAuth client). Same governance as the Kobo connector.
12. **Maps — NOT STARTED; owner decision needed** (a tile provider, with CSP and privacy consequences, or an offline vector base map). Point locations on observations and activities and a map view.
