## Fixture and role method

Create one uniquely named owned disposable database; apply frozen1→39 checksum migrations followed by explicitly unledgered0040 draft. Capture exact applied1→39 hashes and separately identify draft hash. Use trusted fixture-superuser writes solely to establish storage-valid synthetic data, existing genuine fixture tenant/principal/membership identities, explicit synthetic export grants, and negative expired/unavailable pins. Retained negative records must satisfy schema/FKs/deferrable seals; never edit an old revision or disable RLS/immutable triggers.

The native probes in native_probe_helpers.py connect to actual APP, EXECUTOR, WORKER, IDENTITY and PLATFORM logins and always SET LOCAL ROLE to that login's existing privilege role. APP and EXECUTOR are distinct NOINHERIT logins using impact_app. Missing/wrong DSNs fail the native test, never silently fall back to fixture SET ROLE. For NOLOGIN roles impact_privacy/impact_sensitive/impact_observer, any additional fixture-superuser SET ROLE probe must be explicitly labelled role-policy evidence, not actual native-login evidence. No connection exception text or DSN/environment secret is written to reports.

A legitimate complete issuance is created in one transaction after resolving a current selected member: obtain database generation time; build bounded canonical bytes and digest; store.write one closed Recorded AuditEvent(action issue_ai_plan_export, subject plan, exact issuer/correlation/time, track_author=False); use its object/revision as issuance ID/audit revision; insert metadata; bytes; one AuditEvent-aggregate object.changed intent and channel-null delivery row; exact pointer-only receipt. Every remaining row commits with the deferred seal. This avoids a shared writer/API schema change. No plan payload/head changes.

## Structural and privilege checks

1. Inspect pg_class FORCE/ENABLE RLS for both new tables; inspect ACLs for APP SELECT/INSERT only, no runtime UPDATE/DELETE. Non-owner actual logins cannot SET ROLE impact_owner or write approved profile registry. Profile row/hash equals proposed-bootstrap-profile.json; old0036 row unchanged.
2. Legitimate current issuer succeeds under APP and sees exact metadata/body/digest; another principal with the same tenant read/export grants sees zero issuer rows. Actual EXECUTOR without resolved principal sees zero private rows/pointers. Another tenant, empty tenant, empty principal, malformed principal and wrong role also fail closed.
3. Separate direct/table grants and group-entitlement scope paths: read without export, export without read, out-of-scope plan, inactive group/expired entitlement, inactive principal, inactive/suspended/revoked or expired membership, inactive tenant, RESTRICTED current classification/head, unavailable exact older pin with a readable newer head. All ten new pointer classes are hidden. AVAILABLE noncurrent pin remains exportable. Current app session assurance/cutoff checks remain API responsibilities and require API tests; the GUC does not claim to authenticate a human against a compromised app login.
4. Connection reuse: valid context first; transaction ends; assert GUC/role cleared; next transaction with missing principal hides rows. Malformed principal yields NULL rather than a casting error. Both APP/EXECUTOR checked with actual logins.
5. Tenant-qualified typed FKs: foreign tenant plan/member/principal/snapshot/audit/outbox, wrong plan or audit revision type, same-tenant different object's revision, and mismatched issuer/member all refused. Metadata referencing another member must not pass INSERT RLS merely because both memberships are active.
6. Byte guard: declared count/hash mismatch, size0/1 or >1MiB fails; exact bytes stored. Original metadata time+168hours deadline; any other deadline fails CHECK. UPDATE/DELETE metadata/body refused for APP by ACL and fixture owner by immutable trigger. Existing owner/migrator roles are not broadened.
7. Audit binding: wrong action/outcome/actor/effective actor/plan/correlation/time, NULL omitted required audit fields, nonfirst revision, current-head mismatch or mismatched audit projection fails deferred commit. Extra issued-AuditEvent revision/head changes refused. Issuance ID is the AuditEvent ID and exact revision FK is verified.
8. Completeness: attempt export AuditEvent-only, issuance without bytes, wrong/missing receipt, missing/mismatched outbox or channel-null delivery; SET CONSTRAINTS ALL IMMEDIATE or commit fails, rollback leaves no metadata/audit/body/receipt/event. No durable unprojected export audit visibility bypass. Normal unrelated AuditEvent writes and existing human-advice participant privacy still work.
9. Receipt: exact nine pointer/digest fields only, original actor/operation/request hash/time/correlation/content/count/deadline. Wrong values or extra text/body/private fields fail receipt policy/seal. Bytes never appear in operation_receipt, AuditEvent or outbox payloads.
10. Permanent operation uniqueness: duplicate tenant/principal/command/operation refused even with another format/revision/issuance. After a storage-valid expired fixture and actual retention_purge_receipts call under WORKER, metadata/operation uniqueness remains. Current issuer may read metadata to report IDEMPOTENCY_EXPIRED but body is hidden; no reconstruction/new issuance under same operation. A new operation can issue only under fresh current authority.
11. Guidance: COMPLETE/PARTIAL binding refers to the exact selected revision's snapshot/digest/schema, never another revision or tenant. Existing binding cannot be relabelled UNAVAILABLE. Missing binding may honestly be UNAVAILABLE. Archive hash/schema verification and closed public allowlist belong to meaningful API/pure tests; SQL does not claim to infer public/private text from arbitrary BYTEA.
12. Pointer surfaces: new metadata/body; generic AuditEvent registry/revisions; audit_event_current and existing audit export query; optional natural-author fixture; operation receipt; outbox event/delivery/consumer. Current exporter scope/member/old-pin refusal removes every pointer, without hidden counts. Other runtime logins cannot read those pointers even after setting a guessed principal GUC or calling helper(app_participant=True). Scope policies coexist restrictively with human advice; direct new helper calls also retain the original human-advice helper refusal. No DROP/ALTER old policy/function.
13. Nondelivery: new intent has channelNULL; WORKER sees no event/delivery/consumer and cannot claim it. APP cannot add an email channel, sent status or mutate delivery. No outcome is described as external delivery.
14. Retained-child removal: try clearing the exact parent plan revision payload as fixture owner (negative SQL, not a supported privacy approval), with metadata/body present; first added guard returns AI_PLAN_EXPORT_CHILD_RETAINED and every row/hash remains. No unsupported PrivacyCase scope/store_action is inserted. Expired bytes still block removal because expiry is not deletion. Unrelated existing guard refusals remain. This proves protective refusal, not an operated erasure flow, retention duration or restore acceptance.
