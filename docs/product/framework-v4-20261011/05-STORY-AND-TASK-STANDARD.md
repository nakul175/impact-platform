## Refined eight-tier authoring and evidence standard — 11 October 2026

Every tier names its beneficiary/outcome, source/alignment, boundary, assumption, evaluation and actual decision state. Vision sets the durable benefit/population; strategy states choices and opportunity cost; roadmap binds the outcome sequence and unchanged release allocations; release goals bind included/excluded scope and exit evidence; epics define capability handoffs/shared controls; stories define actor/state/action/benefit; criteria define observable behaviour/refusal; technical tasks define inputs, outputs, interfaces and completion evidence. Technical tasks and criteria both belong to the story, with explicit task-to-criterion links.

Use stable IDs from the existing source. Two supplementary criterion ID formats in the author proposals refer to the same scenario: `<story>-AC-<two-digit ordinal>` and `AC-<story>-<three-digit ordinal>`. The edition's criterion-alias map joins them by exact source story/scenario ordinal and source hash; they are not extra requirements. Supplemental control plans use separate identities and remain proposals. Preserve original Gherkin even when a phase is missing; present recommended context separately for review. Existing plan assertions that add to original Then clauses are labelled supplementary, never silently substituted for the source.

Task contract: parent story and source criterion aliases; exact original core/hash; prerequisite task IDs; permitted input revision/actor/policy; proposed output and interface boundary; current-code reuse anchors; data/API/UI/NFR impact; assumptions/clarifications; observable completion method and protected side effects; evidence record with actual candidate/environment/results/artifact. Estimates and assignees stay unset where not established. Qualification ownership is explicit even where the old task list lacks a qualification-kind task; a proposed role is not a named human assignment.

AI applicability is assessed per slice from source/code/data flow, not inferred only from the word AI. If a task touches an AI dependency or derived content, apply the seven strategy groups and source NFR/AI scenarios. If applicability is unknown, keep it unresolved; a negative flag alone cannot waive it. Official calculations, tenant/current authority, independent approval and immutable history remain shared constraints.

**Framework evidence:** run the unmodified attached checker in real planning mode, then summary → next → authored fix → check again. Archive exact inputs/source pins and reports. Structural/local checks, semantic review, external authorised-review trust, actual product execution and owner acceptance are distinct. Missing real reviewer/trust evidence stays unresolved; do not substitute synthetic examples, fake identities or catalogue edits to obtain a pass. Review the actual most consequential assumptions and strongest adverse cases first, rather than add prose to fill fields.
