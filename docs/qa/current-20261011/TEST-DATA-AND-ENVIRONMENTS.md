## Preparation, isolation and cleanup procedure

1. Freeze actual candidate/source/artifact/config and case/oracle population; identify the authorized environment/data owner, required actors and secret references. Inspect the implemented contracts, fixture and current migration ledger before setup.
2. Use an owned disposable checkout/state/database and unique API ports. `scripts/run.py` creates `.local/test-<unique>` for test/browser modes; native provisioning still requires an operator-approved disposable database. Separate actors/tenants and record their current authority. Do not invent a synthetic/system/loginless approver to bypass a required natural-person decision. Existing synthetic fixture actors model checks; they do not provide real acceptance or release approval.
3. Preserve the existing fixture preflight. `scripts/run.py` compares the manifest expiry with `scripts/fixture_support.py` and refuses when fewer than 90 days remain. If needed, an authorized fixture maintainer versions the complete generated fixture via `scripts/redate_fixture.py`; a test must not edit one date, runtime policy or historical source to bypass expiry. No redating occurs in this documentation step.
4. Use the existing governed loader/migration runner only for permitted disposable targets. `specification/fixtures/load.py` requires its explicit enable flag and fixture connection; seed controls and the target-name/empty-state safeguards are separate and must be verified before use. Never remove operational data or weaken forced RLS. Time control belongs in the authorized harness, not an attacker-supplied production header.
5. Register expected created objects and external sink boundaries. Preserve the same operation ID/body for an exact retry; changed intent needs a new operation. Restore mutable test state through audited correcting revisions where required. Failed cleanup fails/quarantines that fixture; it does not justify deleting history. Reset through authorized disposal/new state.
6. Run only the agreed selection, with isolated report ownership. Default `docs/evidence/application-tests.xml`, native and browser reports are mutable paths; archive each attempt under a unique controlled run ID with raw logs and hashes before another invocation can overwrite it. Preserve failures and subsequent retests separately. Do not silently restore over the only copy of a failed run.
7. Verify owned processes are stopped, inspect actual cleanup results and control fixture/credential retention. Dispose only the owned synthetic environment under its procedure; preserve decision-relevant immutable evidence. Access owner, evidence retention period, approved store/confinement and credential expiry/disposal record remain pending, so no arbitrary retention duration is declared here.
