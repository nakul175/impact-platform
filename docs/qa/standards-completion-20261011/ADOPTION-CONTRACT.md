## Recommended decision defaults

- **Preparation scope:** enumerate every active source criterion regardless of mapping or applicability; narrow future actual delivery scopes only through a new complete independently reviewed source snapshot.
- **Data:** synthetic fixtures and controlled provider responses for isolated development; prepare real-data/corpus permission decisions before using them. A budget or account credential cannot provide those rights.
- **Risk:** use the existing impact/likelihood method and explicit source-backed provisional assumptions. Unknown exposure/likelihood is a decision gap; do not imply evidence-based residual risk or an approved Low classification.
- **Routing:** continue one current story at a time with supporting reviews/testing. The package's Low-tier fast path is available only after actual Low classification and unchanged nonwaivable controls; it never bypasses the working agreement or required CI.
- **Targets:** retain original numerical targets. Bind versions, numerator/denominator, slices, windows, repetition/uncertainty and actual approval before qualification. No invented generic performance target or 4-of-5 success rule replaces source requirements.
- **Records:** serialize integrations; separate concurrent authoring drafts; preserve exact source/attempt/event/selection versions and failures. Referenced fictional examples never enter product run registers.
- **Source protection:** retained CODEOWNERS is a real file, while enforcement is NOT_VERIFIED. Do not falsely mark controls absent, configured, or passed. Main auto-deploys; no documentation-only request provides merge/deploy permission.

These defaults make the documents usable now. They deliberately leave decisions requiring actual people, runtime observations or external authority open; a locally typed name/path is not proof of any of them.

## Bounded pilot dossier

Before the selected story's first qualification attempt, complete a dossier with: original story/criteria and reviewed source pins; chosen case versions and meaningful bindings; actual independent executor/reviewer; risk/threshold/repetition contracts; current candidate/artifact/schema/environment/config/data pins; fixture/role/permission identities; exact affected assertions and native/browser/provider/specialist scope; owned capture locations; first-failure retention; and applicable financial/data/release authority.

After execution, append actual run evidence, observed effects/absences, defects and retests, coverage-selection snapshot, honest readiness report and authentic decisions. Missing expected/observed evidence, infrastructure failure, stale authority or a skipped required assertion cannot become PASS. Source preservation and planning checks do not execute this pilot.

## Sustain and invalidation

Material source, case, configuration, model/prompt/corpus, policy, role, environment or code changes require an impact decision and invalidate affected prior qualification. Preserve that decision and the old evidence; do not silently replace selected failure with a diagnostic rerun. Review exception expiry, incident/flakiness/escaped defects, user outcomes, source coverage and evidence access at the actual operating cadence. Update roadmap/risk from observations with actual denominators and uncertainty; predicted value remains separate.

The process is NOT_READY for release decisions until genuine source protection, current required evidence and actual authorities are established. The documentation may be authored and published while those gates remain open.
